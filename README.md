# Poker Club — Telegram Mini App

Готовый MVP спортивного покерного клуба: мобильное Telegram Mini App, защищённая админка, API, PostgreSQL и Telegram-бот.

## Что уже работает

- авторизация через подписанный `Telegram.WebApp.initData`;
- самостоятельная регистрация и вход из браузера по почте/паролю, одноразовому коду из Telegram или адресному приглашению администратора;
- доступ в админку только для ID из `ADMIN_TELEGRAM_IDS`;
- главная страница с карточкой игрока, регистрацией на ближайший турнир, задачкой, результатами, советом и лидерами сезона;
- календарь турниров, сезонный и недельный рейтинг, профиль игрока;
- самостоятельная регистрация на турнир, лист ожидания и автоматический перевод на освободившееся место;
- автоматическая рассадка по столам с настраиваемой вместимостью, ручными перестановками и публикацией мест игрокам;
- создание сезонов и турниров;
- редактирование турниров, статусов и сезонов из единого рабочего пространства;
- ввод результатов расстановкой игроков по местам;
- ручное начисление и списание очков конкретному игроку;
- атомарное пакетное начисление очков по итогам турнира и безопасная отмена ошибочной проводки;
- Telegram-уведомления об очках и изменениях регистрации;
- персональные Telegram-уведомления с номером стола и места после публикации рассадки;
- добровольная передача телефона через нативное подтверждение Telegram с резервной кнопкой в боте;
- еженедельные шаблоны турниров с автоматическим заполнением расписания;
- приватные заметки, теги и расширенные фильтры игроков;
- отдельный аудит всех значимых действий администратора;
- смена общего цвета интерфейса и фонового изображения рейтинговой карточки без нового деплоя;
- финализация сезона с неизменяемым снимком итогового рейтинга;
- журнал операций: причина, администратор, сезон и баланс после изменения;
- Telegram-бот с командами `/start`, `/app`, `/login` и `/phone`;
- постоянные плиточные меню игрока и администратора с автоматическим выбором по Telegram ID;
- inline-панель управления с безопасными deep link-переходами к фактическим разделам Mini App;
- подтверждаемая Telegram-рассылка по выбранной аудитории с предпросмотром и записью результата в аудит;
- рассылка напоминания о турнире всем пользователям, запускавшим бота;
- адаптивный интерфейс админки для телефона и компьютера;
- отдельная адаптация шапки и управляющих кнопок под safe area Telegram на iPhone;
- центральный турнирный экран **MAIN** с визуальным столом, участниками, чек-ином, рассадкой, турнирными операциями, результатами, PTS и таймером;
- быстрые серверные операции ребая, повторного входа, выбывания, баунти и бонусного Club XP с записью в аудит;
- отдельный бонусный баланс Club XP, ежедневные советы и интерактивные раздачи;
- серии посещений, достижения и защищённая реферальная программа;
- расширенный профиль с вкладками статистики, наград, истории и приглашённых друзей;
- административный центр лояльности с редакторами контента и журналом Club XP;
- отдельная аналитика клуба: явка, неявки, рост аудитории, активность, рефералы, доставка уведомлений и CSV-отчёт;
- компактное меню администратора с карточкой игрока и быстрыми действиями;
- единый deployment Vercel Services для Vite + Express и PostgreSQL через Vercel Marketplace.


## Центральный раздел MAIN

Для каждого текущего турнира MAIN открывает отдельное рабочее пространство. Слева расположен визуальный зал со столами до 10 мест, переключением, созданием, закрытием, изменением вместимости, ручной посадкой, переносом и обменом игроков. Под столом находится список участников без места. Справа работает общий серверный таймер с блайндами, анте, уровнями, перерывами, полноэкранным режимом и публичной ссылкой для телевизора без авторизации.

Ниже доступны карточки игроков с прямыми действиями чек-ина, ребая, re-entry, выбывания, баунти и бонусного Club XP; единые результаты и пакетное начисление PTS; журнал операций. Баунти одновременно отмечает цель выбывшей и освобождает её место. Все изменения сохраняются через API и отражаются в аудите.

Раздел **Турниры** используется для создания, настроек, шаблонов и архива. Операционные действия по участникам, рассадке, таймеру и результатам открываются в MAIN для выбранного турнира.

## Доступ из браузера

Самостоятельный сценарий по почте:

1. Пользователь открывает `/browser-login` на сайте.
2. Выбирает **Регистрация**, указывает имя/никнейм, почту и пароль.
3. Получает обычный профиль игрока и отзывную браузерную сессию на 30 дней.

Аккаунт по почте не получает административных прав. Админка доступна только Telegram-профилям, чей числовой ID присутствует в серверной переменной `ADMIN_TELEGRAM_IDS`.

Вход по Telegram-коду также сохранён:

1. Пользователь в личном чате с ботом отправляет команду `/login`.
2. Бот выдаёт восьмизначный одноразовый код на 10 минут.
3. Пользователь вводит код на сайте и получает сессию существующего Telegram-профиля.

Код хранится только как SHA-256-хеш, предыдущий неиспользованный код аннулируется при выпуске нового, а использованный код нельзя применить повторно.

Администраторский адресный сценарий также сохранён:

Адресные приглашения администратора для существующих Telegram-профилей также сохранены:

1. Пользователь хотя бы один раз открывает Mini App через Telegram, чтобы появиться в БД.
2. Администратор открывает раздел **Доступ**, выбирает пользователя и создаёт приглашение.
3. Ссылка действует 30 минут, принимается только один раз и должна передаваться лично.
4. После первого открытия браузер получает персональную сессию на 30 дней.
5. Администратор видит активную сессию и может немедленно отозвать её в том же разделе.

В PostgreSQL сохраняется только SHA-256-хеш одноразового токена. Сам токен показывается администратору один раз. Каждая браузерная сессия имеет отдельный идентификатор, срок действия и отметку отзыва; API проверяет её на каждом защищённом запросе. Отзыв не влияет на обычный Telegram-вход пользователя.

## Учёт очков

В MAIN очки предзаполняются по занятому месту и начисляются всем игрокам одной атомарной операцией после сохранения результатов. Значения можно скорректировать до начисления. Индивидуальные начисления и списания по-прежнему доступны в разделе **Игроки**.

Для надёжности используются две связанные сущности:

- `User.points` — текущий баланс активного сезона для быстрого рейтинга;
- `PointTransaction` — журнал каждого начисления, списания и встречной проводки с итоговым балансом;
- `PointBatch` — атомарная группа операций по конкретному турниру.

Изменение выполняется в serializable-транзакции PostgreSQL: обновление баланса и запись журнала либо сохраняются вместе, либо полностью отменяются. Отрицательный баланс запрещён, повторная отправка той же операции защищена idempotency-ключом.

Пакет турнира выполняется целиком в serializable-транзакции и может быть создан только один раз. Значения PTS записываются и в `TournamentResult`, поэтому итоговый протокол совпадает с балансами. Если администратор ошибся, исходная запись не удаляется: сервер создаёт равную по модулю встречную проводку и синхронно корректирует результат турнира. При завершении сезона рейтинг сохраняется в `SeasonStanding`, после чего операции этого сезона изменить нельзя.

## Club XP и программа лояльности

`Rating PTS` остаётся спортивным рейтингом сезона. Советы, достижения, приглашения и раздача дня используют отдельный баланс `User.clubXp` и журнал `ClubXpTransaction`; бонусные действия никогда не меняют `User.points`.

Совет выбирается случайно при каждом открытии главной страницы; при наличии нескольких активных советов непосредственный повтор исключается. Покерная ситуация выбирается стабильно на календарный день клуба. Контент запрашивается отдельным API после загрузки главной страницы, поэтому не замедляет авторизацию и основные экраны. До ответа сервер не отправляет клиенту объяснения и правильный вариант. После ответа выбранный разбор остаётся открытым, а остальные объяснения можно независимо раскрывать и сворачивать. Повторный ответ в те же календарные сутки блокируется уникальным ограничением БД; интерфейс показывает отсчёт до полуночи в `CLUB_TIMEZONE`.

Реферальная ссылка ведёт в Telegram-бота. Код принимается только при создании нового пользователя, а награда остаётся в статусе ожидания до первого подтверждённого чек-ина. После него Club XP пригласившему и новичку выдаются одной serializable-транзакцией. Повторное начисление невозможно благодаря уникальным idempotency-ключам.

Раздел **Лояльность** в админке позволяет без деплоя менять размеры наград и срок серии, включать модули, редактировать советы, раздачи и достижения, отклонять подозрительные ожидающие приглашения и вручную корректировать Club XP с обязательной причиной.

## Регистрация и лист ожидания

Игрок нажимает **Участвовать** в карточке предстоящей или уже активной игры. После старта работает поздняя регистрация: она остаётся открытой до ручного закрытия администратором или заданного дедлайна. Пока есть места, заявка попадает в основной список; затем новые заявки переходят в очередь.

Администратор во вкладке **Участники** может добавить игрока вручную, подтвердить приход, отметить участие, перевести в очередь или отменить заявку. Чек-ин подтверждается строго после выдачи фишек и не отменяется ни в интерфейсе, ни прямым запросом к API. Обычный пользователь может сам отменить только заявку на ещё не начавшуюся игру.

## Пятиминутный сценарий администратора

Админка по умолчанию открывает экран **Сегодня** и сама выбирает турнир, который требует работы: активный, просроченный предстоящий, незакрытый после игры или ближайший будущий. Сверху показана цепочка **Заявки → Чек-ин → Рассадка → Игра → Результаты → Очки**, а большая кнопка всегда ведёт к следующему безопасному действию.

Типичный цикл:

1. Проверить заявки и при необходимости отправить напоминание.
2. Открыть быстрый чек-ин и нажать только на реально пришедших игроков.
3. Сформировать рассадку, проверить столы и опубликовать места.
4. Запустить турнир — регистрация останется открытой для поздних участников до ручного закрытия или дедлайна.
5. В результатах одним нажатием загрузить пришедших. В режиме выбывания отмечать игроков в порядке выхода из игры.
6. Сохранить места, проверить суммы и начислить очки одним атомарным пакетом.

Черновик порядка мест, прогресса выбывания и сумм автоматически хранится в браузере до серверного сохранения результатов. Массового чек-ина намеренно нет: эта операция должна отражать реальное присутствие каждого человека.

## Рассадка игроков

В разделе **Рассадка** администратор выбирает турнир, количество мест за столом и при необходимости точное число столов. Сервер случайно и равномерно распределяет зарегистрированных игроков; разница в заполнении столов не превышает одного человека. Можно ограничить выбор только прошедшими чек-ин.

Игрока можно выбрать нажатием, затем перенести на свободное место или поменять местами с другим игроком. Любое ручное изменение снимает публикацию, чтобы игроки не видели устаревшие данные. После проверки администратор публикует рассадку: место появляется на главной странице Mini App, а бот отправляет каждому номер стола и места.

Seed случайной рассадки, генерация, перестановки, снятие с места, публикация и скрытие записываются в аудит. Завершённые и отменённые турниры защищены от изменения рассадки.

## Турнирный таймер

В карточке турнира администратор открывает вкладку **Таймер**. При первом открытии создаётся базовая структура с уровнями по 15 минут и двумя перерывами; её можно полностью заменить. Для каждого игрового уровня задаются малый и большой блайнд, анте и длительность. Для перерыва задаются название и длительность.

Во время игры доступны запуск, пауза, продолжение, переход назад или вперёд, выбор любого уровня, быстрые `+1` и `+5` минут и сброс. Кнопка **Большой экран** открывает адаптивное табло для телевизора или ноутбука. Игроки видят ссылку на табло в карточке активного турнира после того, как таймер настроен, но не получают права управления.

Сервер хранит момент запуска и оставшееся время. Если страница закрылась, устройство сменилось или serverless-инстанс был остановлен, после возвращения таймер рассчитывает фактический уровень и остаток, включая переход через несколько этапов. Запуск таймера переводит предстоящий турнир в активный статус, но не закрывает позднюю регистрацию.

## Телефоны и оформление

В профиле игрок может изменить отдельный клубный никнейм и загрузить JPG, PNG или WebP. Браузер обрезает фотографию до квадрата и уменьшает её до 512 × 512, после чего API выполняет подписанную загрузку в Cloudinary. В PostgreSQL сохраняются только ссылка и `public_id`; Cloudinary API secret остаётся только в server-side переменных Vercel. Telegram-фото намеренно не используется как стандартный аватар: без собственной фотографии показывается временная клубная заглушка. Аватар в шапке приложения открывает профиль.

Там же игрок может добровольно нажать **Поделиться**. Telegram показывает системное окно подтверждения и отправляет боту только собственный контакт пользователя. Бот создаёт профиль даже при первом контакте, проверяет Telegram ID и сохраняет номер; Mini App ждёт подтверждения БД и при задержке показывает резервную кнопку. Команда `/phone` предоставляет тот же сценарий через чат с ботом.

Общий цвет меняется в **Настройки → Оформление клуба** и применяется ко всему интерфейсу для всех пользователей. Можно выбрать готовый вариант или произвольный цвет. Там же меняется фон рейтинговой карточки: браузер обрезает и уменьшает PNG, JPEG или WebP перед сохранением в PostgreSQL.

## Структура

```text
apps/
  api/                  Express API, Telegram-бот, Prisma
    prisma/             схема, десять миграций и демо-данные
    src/routes/         пользовательские и админские API
  web/                  React/Vite Mini App и админка
vercel.json             Vercel Services: web + API + Cron

```

## Локальный запуск

Нужны Node.js 20+ и Docker.

```bash
docker compose up -d
npm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте `http://localhost:5173`. В примере включён локальный демо-вход для Telegram ID `111111111`; он совпадает с демо-администратором из seed.

Перед production обязательно отключите демо-вход: не задавайте `ALLOW_DEV_AUTH` или установите `false`.

## Создание бота

1. Откройте `@BotFather` в Telegram.
2. Выполните `/newbot`, задайте имя и username.
3. Сохраните выданный токен — он понадобится только в server-side переменной `TELEGRAM_BOT_TOKEN` на Vercel.
4. После деплоя отправьте боту `/start`. Кнопка Mini App появится в ответном сообщении.
5. При желании задайте постоянную кнопку меню через `/setmenubutton` в BotFather, указав Vercel URL.

Токен нельзя добавлять в Git или в файлы `.env.example`.

## Деплой всего приложения на Vercel

Проект подготовлен к единому deployment: Vite-интерфейс и Express API находятся под одним доменом, PostgreSQL подключается через Vercel Marketplace. Подробная пошаговая инструкция, включая перенос существующей Render PostgreSQL, находится в `VERCEL_MIGRATION.md`.

Кратко:

1. Импортируйте репозиторий в Vercel из корня и выберите Framework Preset **Services**.
2. Подключите Neon/Postgres через **Storage / Marketplace**. Runtime использует pooled `DATABASE_URL`; для миграций желательно добавить `DATABASE_URL_UNPOOLED` или `DIRECT_URL`.
3. Добавьте серверные секреты (`JWT_SECRET`, `CRON_SECRET`, Telegram, Cloudinary и т. д.).
4. Выполните production deploy. Prisma-миграции применятся во время production build API.
5. Проверьте `https://ВАШ-ДОМЕН/api/health`.
6. Один раз настройте Telegram webhook через `POST /api/internal/telegram/setup` с заголовком `Authorization: Bearer <CRON_SECRET>`.

В production `VITE_API_URL` больше не требуется: интерфейс обращается к `/api` на том же домене. Это убирает отдельный API-домен и большую часть CORS-конфигурации. Preview deployments по умолчанию не запускают миграции production-БД; для отдельной preview-базы можно установить `RUN_MIGRATIONS=true`.

## Как назначить администратора

Числовой Telegram ID отображается прямо на странице **Профиль**. Добавьте ID в `ADMIN_TELEGRAM_IDS` на Vercel и выполните redeploy. При следующем открытии Mini App пользователь получит роль администратора и увидит кнопку со щитом.

Если ID несколько, перечислите их через запятую без пробелов или с пробелами — оба формата поддерживаются.

## Первичная настройка клуба

1. Зайдите в Mini App аккаунтом администратора.
2. Откройте кнопку со щитом или блок **Управление клубом** в профиле.
3. Создайте активный сезон.
4. Создайте ближайший турнир.
5. Игроки записываются сами; при необходимости управляйте списком во вкладке **Участники**.
6. Перед игрой откройте **Рассадка**, задайте размер столов, сформируйте и опубликуйте места.
7. В карточке турнира откройте **Таймер**, проверьте уровни и запустите отсчёт.
8. После игры откройте **Турниры → Результаты**, расставьте игроков, сохраните места, проверьте суммы и нажмите **Начислить всем**.
9. Для индивидуальной корректировки откройте **Игроки → Баланс**. Ошибочную операцию можно отменить из истории.
10. В конце сезона нажмите **Настройки → Завершить** и подтвердите сохранение итоговой таблицы.

## Рабочее пространство администратора

- **Сегодня** — текущий турнир, этапы рабочего цикла, следующее действие, исключения, показатели клуба и быстрые действия.
- **Игроки** — расширенный поиск; очки, безопасная отмена, заметки, теги, результаты и персональный браузерный доступ.
- **Турниры** — параметры, турнирный таймер, регистрация, очередь, шаблоны, уведомления, результаты и пакетное начисление.
- **Рассадка** — автоматическое распределение, ручные перемещения, столы, публикация и Telegram-уведомления.
- **Лояльность** — Club XP, советы и раздачи дня, достижения, рефералы и бонусный журнал.
- **Аналитика** — периоды 7/30/90 дней или сезон, сравнение с предыдущим периодом, явка, активность, эффективность и выгрузка CSV.
- **Аудит** — фильтруемый журнал действий с состоянием до и после изменения.
- **Доступ** — создание приглашений, поиск активных сессий и их отзыв.
- **Настройки** — сезоны и их финализация, оформление рейтинговой карточки, шаблоны причин и теги игроков.

На телефоне меню состоит из четырёх пунктов. Разделы **Аналитика**, **Лояльность**, **Рассадка**, **Аудит**, **Доступ** и **Настройки** находятся внутри **Ещё**.

Активация другого сезона сбрасывает текущие значения `User.points` до нуля, но не удаляет историю операций. Интерфейс требует отдельного подтверждения. Повторное редактирование уже активного сезона баланс не сбрасывает.

Пользователь появляется в БД после первого открытия Mini App либо первого `/start`, `/login` или передачи контакта в боте. Повторный `/start` и повторная передача номера обновляют существующий профиль по уникальному Telegram ID и не создают дубликаты. Чтобы бот мог отправлять уведомления, пользователь должен открыть личный чат с ним.

## Меню Telegram-бота

После `/start` сервер синхронизирует профиль и проверяет Telegram ID по `ADMIN_TELEGRAM_IDS`. Игрок получает компактную постоянную клавиатуру с клубом, турнирами, профилем, рейтингом, помощью и нативной передачей контакта. Администратор получает отдельное операционное меню и inline-панель.

Скрытие административных кнопок не используется как защита: каждый callback, каждый шаг рассылки и каждое административное текстовое действие заново проверяют Telegram ID на сервере. Callback-навигация редактирует текущее сообщение, вложенные экраны имеют кнопку возврата, а устаревшее сообщение безопасно заменяется новым.

Фактические адреса Mini App сохранены: турниры открываются через `/games`, а административные функции — через `/admin?section=...`. Отдельные дублирующие страницы не создаются. Админка читает query-параметры `section`, `intent` и `target`, чтобы сразу открыть нужную существующую вкладку.

Рассылка выполняется только после последовательных шагов: аудитория → текст → предпросмотр → подтверждение. Доступны все игроки, активные за 30 дней и участники ближайших/активных турниров. Черновик живёт 30 минут, повторное подтверждение не запускает вторую отправку, итог записывается в аудит.

## Основные переменные окружения

| Переменная | Где | Назначение |
|---|---|---|
| `DATABASE_URL` | Vercel API | Pooled-подключение PostgreSQL для runtime |
| `JWT_SECRET` | Vercel API | Подпись сессии Mini App |
| `TELEGRAM_BOT_TOKEN` | Vercel API | Проверка Telegram-входа и работа бота |
| `TELEGRAM_WEBHOOK_SECRET` | Vercel API | Защита webhook бота |
| `MINI_APP_URL` | Vercel API, необязательно | Production URL для кнопок бота; при отсутствии берётся системный Vercel URL |
| `ADMIN_TELEGRAM_IDS` | Vercel API | Белый список администраторов |
| `ADMIN_CONTACT` | Vercel API, необязательно | Контакт администратора для раздела «Помощь», например `@username` |
| `CLUB_TIMEZONE` | Vercel API | Часовой пояс уведомлений, для Копейска/Челябинска `Asia/Yekaterinburg` |
| `CLOUDINARY_CLOUD_NAME` | Vercel API | Cloud name проекта Cloudinary |
| `CLOUDINARY_API_KEY` | Vercel API | API key Cloudinary |
| `CLOUDINARY_API_SECRET` | Vercel API | Новый API secret Cloudinary, только сервер |
| `VITE_API_URL` | Vercel Web, необязательно | В production не нужен; используется same-origin `/api` |

## Важные замечания

- Это система клубных очков, а не денежных ставок: платежей, кошельков и вывода средств в коде нет.
- API использует проверку Telegram-подписи, JWT, Helmet, CORS, общий PostgreSQL-лимит попыток авторизации и HTTP-сжатие.
- Serverless API и Neon могут scale-to-zero при простое; первое обращение после паузы иногда имеет повышенную задержку.
- Перед большим запуском рекомендуется перейти на постоянный тариф PostgreSQL и настроить резервные копии.

## Google Sheets для заявок на обучение

Форма бесплатного обучения включается в админке: **Настройки → Бесплатное обучение по покеру**. Администратор вставляет обычную ссылку вида `https://docs.google.com/spreadsheets/d/...` и включает показ формы игрокам.

Чтобы API мог добавлять строки в таблицу:

1. Создайте Google Cloud service account и включите Google Sheets API.
2. Добавьте в Vercel переменные `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_PRIVATE_KEY`.
3. Откройте указанную Google-таблицу и выдайте service account права **Редактор**. Его email показывается прямо в карточке настроек.

Строки добавляются в первые семь колонок: время заявки, ФИО, телефон, удобное время связи, удобное время визита, профиль пользователя, внутренний user ID. Каждая заявка сначала сохраняется в PostgreSQL. Если Google временно недоступен, в настройках появится счётчик и кнопка повторной синхронизации.
