# Ряд — fullstack демо маркетплейса

Next.js 16, React 19, серверные API, SQLite локально / PostgreSQL на Vercel.

## Запуск

Node.js 22.13+ (рекомендуется 24), npm.

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000. Локальная база `.data/market.db` создаётся автоматически. Сохраните её отдельно, если нужны резервные копии локальных демоданных.

```bash
npm test
npm run build
npm start
# В другом терминале при запущенном приложении:
npm run test:api
```

## Размещение на Vercel

1. Загрузите содержимое этой папки в новый репозиторий GitHub. В архив не включены секреты, node_modules или база гостей.
2. Импортируйте репозиторий в Vercel. Framework: Next.js. Root Directory: папка с package.json. Node.js: 24.x. Build: npm run build. Install: npm ci.
3. Подключите PostgreSQL, например через доступного провайдера Vercel Marketplace. Укажите серверную переменную DATABASE_URL с выданной провайдером строкой подключения. Не добавляйте NEXT_PUBLIC_ к переменной и не публикуйте её в репозитории.
4. Deploy. Таблица guest_workspaces создаётся при первом обращении; пользователю БД нужно право CREATE TABLE. Дальнейшие записи транзакционные, запросы параметризованы.
5. Проверьте гостевой вход, добавление товара в корзину и тестовую оплату. Без DATABASE_URL опубликованный сайт покажет понятное сообщение настройки, а не будет терять данные на временном диске Vercel.

Vercel CLI также поддерживается стандартно: `npx vercel` из папки проекта после входа в ваш аккаунт. Не передавайте пароли или токены в чате.

## Что работает

- Гостевой профиль с серверным сохранением и HttpOnly/SameSite cookie, отдельное пространство на каждого гостя.
- Поиск, категории, товары/услуги, город, цена, проверенные демопродавцы, сортировки, избранное.
- Карточки товаров, услуги с запросом расчёта, запись с датой и проверкой занятости в гостевом пространстве.
- Публикация, фото с оптимизацией в браузере, черновик формы, предпросмотр, редактирование, пауза, архив, модерация.
- Корзина, проверка наличия и серверные цены, разделение по продавцам, mock-оплата и отказ банка, отмена, частичный/полный mock-возврат.
- Состояния исполнения заказа, отзывы после получения, защита от повторного отзыва.
- Воронка с drag-and-drop и выбором этапа, заметки, переписка между двумя деморолями.
- Статистика реальных действий гостя, отдельные суммы продаж, тестовой комиссии 5% и остатка.
- Настройки профиля, поддержка, жалобы, демомодерация, журнал решений.
- Мобильная навигация, адаптивные сетки, клавиатурные формы и диалоги, состояния ошибки/пустоты/загрузки.

## Границы этой версии

Это тестовый fullstack, не готовая коммерческая площадка. Все продавцы и рейтинги в начальном каталоге вымышлены, фотографии иллюстративные. Переписка, публикации и покупки не видны другим гостям. Раздел администратора открыт только для тестирования изолированного пространства; это не обход прав на общие данные.

Реальные регистрация, общий каталог продавцов, роли и проверка бизнеса, эквайринг, выплаты, логистика, SMS/email, календарь работников, юридические документы и фискализация пока не подключены. Нельзя принимать реальные платежи в этой версии. Комиссия 5% — настраиваемый далее пример, не финансовое обязательство.

Цифровой рубль: выделена граница платёжного модуля (`lib/payments.mjs`), статус способа оплаты disabled. Банковский API и интеграция не реализованы; необходимы конкретный партнёр, договор и документация. Добавление названия способа оплаты не является интеграцией.

Данные каждого гостя хранятся одним документом: это позволяет быстро проверить UX, но не заменяет нормализованную схему для полноценной торговли. Для публичного коммерческого запуска нужны отдельные таблицы users, shops, memberships, listings, orders, payments, inventory, messages; роли; миграции; внешнее хранение изображений; журнал платёжных событий; подписанные webhooks; idempotency для реального провайдера; rate limiting; мониторинг и резервное копирование PostgreSQL с проверкой восстановления. Очистку старых гостевых сессий следует настроить до широкой публичной раздачи демо.

Текущая cookie гостя живёт 30 дней. При удалении cookie доступ к этому пространству теряется. Реальные личные данные в демо вводить не следует.

## Структура

- `app/page.jsx` — пользовательские сценарии.
- `app/globals.css` — визуальная система и адаптация.
- `app/api/state/route.js` — гостевая сессия, same-origin проверка, API команд.
- `lib/actions.mjs` — серверная валидация и переходы состояний.
- `lib/store.mjs` — SQLite / PostgreSQL, транзакции и контроль версии.
- `lib/payments.mjs` — граница тестового платёжного провайдера.
- `lib/seed.mjs` — демо-каталог и начальные данные.
- `tests/actions.test.mjs` — критические сценарии заказа/возврата/модерации.
- `scripts/check-api.mjs` — интеграционная проверка API.
